{% comment %} The two behaviours every settings list needs, defined once for the page. **The "…" menu's anchoring.** position: fixed and anchored on open, the way templates/components/ui_select.html does it and for the same reason: these rows sit inside .app-content, which is overflow-y-auto, and an absolutely positioned panel is clipped by it. The scroll and Escape listeners are registered ONCE here rather than per row. Two reasons. A list of 200 rows was installing 400 window listeners for a menu of which at most one can be open. And `@scroll.window` never fired at all: .app-content is the scrolling element (templates/base.html), scroll events do not bubble, so a listener on window never saw them and the fixed panel simply drifted away from its row. A capture-phase listener on the document does see them, whatever scrolls. **`bbChanged`.** Whether a response actually changed anything. apps/common/htmx answers both success and refusal with a 204, so `detail.successful` is true for "Tag created" AND for "That tag already exists" — a create form keyed on it wiped what the operator typed on the one response where they needed it back. Only the success path sets the HX-Trigger, which is what this reads. A plain window function rather than Alpine.data(), because every call site also needs flags of its own and spreads this into them: x-data="{ ...bbRowMenu(), renaming: false }" Included from {% templatetag openblock %} block alpine_components {% templatetag closeblock %}, which templates/base.html places after htmx and before the deferred Alpine — so the definitions exist by the time Alpine boots. {% endcomment %}
