{% comment %} The notification bell, mounted in the app header (partials/_app_header.html). **Why the header now:** the redesign gave the shell a real 60px top bar, and the bell is the only unread indicator in the product. It used to live in the sidebar footer because there was nowhere else; it used to have a second copy in the mobile top bar for the same reason. Both of those are gone, and so is the Notifications row in the nav — the header renders on every page including settings, so one bell now covers every archetype. That is why notifications/partials/_badge.html swaps ONE id rather than three. Adding a second copy of this bell anywhere would put two elements on the same id, and an out-of-band swap only ever finds the first. **Why no `{% block alpine_components %}` and no inline script:** `x-data` on a wrapper is the workspace switcher's pattern (base.html:140) — there is no `Alpine.data()` to register, so nothing has to slot into base.html's load-bearing htmx → components → Alpine script order, and there is no inline script to carry a CSP nonce. Inline `x-*` needs `unsafe-eval`, which config/settings/base.py already grants for exactly this reason. {% endcomment %}
{% comment %} Opens downward (`top-full`), and right-aligned. The bell sits at the top-right of the header now, not at the bottom of a sidebar — a panel opening upward from here would run off the top of the window, and one left-aligned would run off the right edge. A separate polling element rather than `hx-trigger="every 60s"` on the button: the button's own request fills the panel, and one element cannot have two targets. `hx-swap="none"` means only the out-of-band badge in the response is applied. Deleting this
is the complete rollback if the poll is ever unwelcome — the open-refetch and the OOB swap keep the count correct without it. {% endcomment %}
