{% load i18n %}{% comment %} The notification bell — now a row in the sidebar's nav, rendered from MAIN_NAV's `notifications` entry via its `partial` field (see partials/_sidebar_items.html). **Why a row again.** It lived in the sidebar footer, then in the appbar, for one reason each time: it is the only unread indicator in the product, so it has to be somewhere every page renders. With the header deleted the sidebar is that surface, and a nav row can carry both the count and the panel — so there is still exactly one way in, and notifications/partials/_badge.html still swaps exactly one id. Adding a second copy of this anywhere would put two elements on the same id, and an out-of-band swap only ever finds the first. **Why the panel is `position: fixed`, teleported, and anchored on open.** Three things have to be true at once and each one rules out the obvious answer. `.sidebar-nav` is `overflow-y: auto`, so an absolutely positioned panel escaping to the right is cut off at the sidebar's edge — and `overflow-x: visible` cannot be expressed alongside `overflow-y: auto`. Hence fixed: templates/components/ui_select.html hit the same wall against a horizontally scrolling toolbar and answered it the same way. But fixed alone is not enough here, and this is the part that looks like it works and does not. The
carries a transform — `-translate-x-full` / `translate-x-0`, which is how the drawer slides — and **a transformed ancestor becomes the containing block for `position: fixed`**. The panel is then laid out inside the sidebar and clipped by that same `overflow-y` after all. `getBoundingClientRect()` reports plausible coordinates throughout, because the sidebar starts at x=0, so the symptom is a panel that is open, has a sensible rect, and paints nothing. Teleporting to takes it out of the transformed subtree; nothing else does, short of dropping the slide animation. The coordinates are captured once, so scrolling the page or the nav closes the panel rather than letting it drift — scrolling the panel's own list does not, see the guard below. One expression covers every width the trigger can have: expanded (right edge 240 → panel at 248), collapsed (60 → 68), and the mobile drawer, where the clamp against `window.innerWidth` pulls a 320px panel back onto a 375px screen instead of off the side of it. Both clamps are two-sided: `Math.min` alone went negative on a short or narrow viewport — a landscape phone computed `375 - 420 = -45` and put "Mark all read" above the top of the window, where a fixed panel cannot be scrolled to. **Why no `{% templatetag openblock %} block alpine_components {% templatetag closeblock %}` and no inline script:** `x-data` on a wrapper is the workspace switcher's pattern — there is no `Alpine.data()` to register, so nothing has to slot into base.html's load-bearing htmx → components → Alpine script order, and there is no inline script to carry a CSP nonce. Inline `x-*` needs `unsafe-eval`, which config/settings/base.py already grants for exactly this reason. Args: item: the resolved nav row (label, active, badge).
