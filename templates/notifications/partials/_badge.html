{% comment %} The unread signal as an htmx **response** fragment. Never included in a page's first render — see _bell.html, which renders the dot inline instead. Including this one at page load would put a second `id="nav-badge-notifications"` in the document beside the nav row's own, and an out-of-band swap resolves its target by id. `hx-swap-oob` lets this ride along inside any other notification response and update the count wherever it is rendered, without the responding view knowing where that is. That is why this is HTML and Studio's equivalent is JSON: htmx swaps markup, and Studio needed a JS callback to turn its number into some. Three targets, because the count appears three times — the footer bell's dot, the sidebar nav row's badge, and the mobile bar's dot, which is the only one a phone reader can see. Leaving any of them stale after "mark all read" shows an indicator contradicting the others. The nav badge is *emptied* at zero, never deleted. An earlier cut deleted it, on the reasoning that the shell renders no badge for a zero count so there is nothing left to update — but _bell.html polls this view every 60s, and a deleted element is one the next poll cannot find, which is `htmx:oobErrorNoTarget` in the console once a minute for the rest of the session. It was worse than a stray log line: the count could then never come *back* up in the page, because every later swap was aiming at an element that no longer existed. The nav row now renders the slot at zero too (partials/_nav_badge.html), so all three targets here are permanent and every swap is a plain `hx-swap-oob="true"`. {% endcomment %}{% spaceless %} {% include "notifications/partials/_dot_slot.html" with key="notification-badge" oob=True %} {% include "notifications/partials/_dot_slot.html" with key="notification-badge-mobile" oob=True %} {% include "partials/_nav_badge.html" with key="notifications" count=unread_notification_count oob=True only %} {% endspaceless %}
