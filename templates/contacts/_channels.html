{% load common_extras i18n %}{% comment %} The contact's channel identities — read-only except for the one-way opt-out. These rows live on apps/messaging's models and this page only reads them. The one mutation goes through apps.contacts.activity → the messaging facade → the single write site in messaging/ingest.py, which is what keeps ROADMAP contract 3 ("opted_out_at is written in one place") literally true rather than true by convention. There is deliberately no un-opt-out. SPEC §19 puts opt-out at a chokepoint so it cannot be bypassed, and a toggle an operator could flip back is a bypass with a friendlier label — re-consent has to come from the contact. `platform_user_id` and `extra.username` are platform-supplied and therefore attacker-controlled (SECURITY-BASELINE §2): rendered escaped, never as a link. {% endcomment %}
