Rendered both inside list.html and on its own for every HTMX refresh — one renderer, so a filtered view and a post-mutation refresh can never disagree about what a row looks like, and the counts above the rows cannot go stale when a switch moves a flow between sections. **Seven buttons became one plus a menu.** Every row used to carry Edit, Stats, Rename, Duplicate, Export, Export bundle and Archive at equal weight, which made the action wanted on nine visits out of ten exactly as prominent as the one wanted twice a year. The named action is now Open — or Continue, for a draft somebody started and left — and the rest sit behind the "…". The menu panel is `position: fixed` and anchored on open, the same way components/ui_select.html does it and for the same reason: these rows live in a scrolling container, and an absolutely positioned panel is clipped by that overflow. The coordinates are captured once, and partials/_list_behaviours.html closes the menu on scroll so it cannot drift away from its button — that listener is registered once for the page, and in the capture phase, because .app-content is what scrolls and a scroll event never bubbles out of it. {% endcomment %} {% comment %} The filter popover's footer reads this after every swap, so "Show N flows" stays true as the selection changes. {% endcomment %}
